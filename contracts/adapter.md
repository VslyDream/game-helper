# Игровой адаптер и сайт

Сайт — представление состояния. Реальные запуск, ввод, камера, сохранения и игровые действия реализует адаптер выбранной игры. Контракт ниже — стартовая граница, а не обязательный язык или движок. При другой архитектуре сохраняются поведение и форма UI.

## Локальный API шаблона

- `GET /api/state` возвращает объект состояния.
- `POST /api/action` принимает JSON `{id, command, args}`; ответ `{ok: true, state, result?}` или `{ok: false, error: "Понятная причина"}`. Успех означает подтверждённый результат. Длительная операция возвращает актуальное состояние `operation`, а завершение видно в следующих статусах.
- `GET /api/commands` — список команд с описаниями и синонимами, `GET /api/screenshot` — кадр игры. Нужны агенту и управлению из чата, сайт их не вызывает; формат — в `modules/mcp/SPEC.md`.
- `apiBase` настраивается в профиле. Сервер использует loopback. Проверяет Origin и защиту от чужих сайтов для меняющих состояние запросов. Предпочтительно отдаёт UI и API с одного адреса.
- Запросы сериализованы в UI; сервер также защищает несовместимые операции. `id` позволяет распознавать повтор одного запроса. Транспортные ошибки сами не повторяют изменяющую мир операцию.

Общая часть состояния:

```json
{
  "connection": "level",
  "gameRunning": true,
  "role": "solo",
  "operation": null,
  "availability": {
    "game.launch": {"enabled": false, "reason": "Игра уже запущена"},
    "game.close": {"enabled": true},
    "freecam.set": {"enabled": true}
  },
  "cheats": {},
  "freecam": {},
  "snapshots": {},
  "replays": {}
}
```

`connection`: `offline`, `closed`, `starting`, `waiting`, `menu`, `level`, `error`. `role`: `solo`, `host`, `client` или пусто. У команды без записи в `availability` кнопка отключена; исключение `enabled` не угадывается из названия игры. Ограничение показывается коротко в подсказке. Сервер не присылает данные невыбранных модулей.

Команды основы: `game.launch`, `game.close`, `cheat.set {id,value}`, `cheat.run {id,values}`. Доступность каждого конкретного чита передаётся ключом `availability["cheat:" + id]`. Конкретные выбранные читы описываются в `config.json → cheats`: категории с `id,title,controls`; контрол имеет `id,label,type` (`toggle`, `range`, `select`, `action`), для диапазона `min,max,step,value,unit`, для списка `options:[{value,label}]`, для разового количества `count:{min,max,step,value,label}`. Это формат UI, не список обязательных читов.

Необязательные поля контрола:

- `hint` — короткая метка клавиши рядом с названием, например `"hint": "H"`. Это только подпись: сам хоткей обрабатывает адаптер, а переназначается он на странице настроек.
- `logarithmic: true` у `range` — шкала растягивает малые значения. Для «×0,1…×20» обычный ползунок держит середину на ×10, и все рабочие значения ×0,5…×3 сжимаются у края; логарифмический ставит в середину ×1,4. Нужен, когда диапазон охватывает несколько порядков (множители, скорость, дистанция). `min` должен быть больше нуля.
- `look: true` — значение контрола входит в пресет образа (только при модуле повторов камеры, `modules/replays/ADAPTER.md`).
- `"type": "pick"` с `catalog` — выбор записи справочника с поиском, только при подключённом модуле «Справочник» (`modules/catalog/SPEC.md`).

## Хоткеи и настройки

`state.hotkeys: [{id,label,keys,default,conflict}]` — хоткеи, которые обрабатывает адаптер. `keys` — строка вида `Ctrl+H`; `conflict` — короткий текст, если комбинация занята игрой или другим хоткеем хелпера. Команды `hotkeys.set {id,keys}` и `hotkeys.reset {id}`; адаптер проверяет конфликты сам и отказывает с понятной причиной. Список известных клавиш игры адаптер собирает при исследовании игры, в том числе встроенные отладочные клавиши разработчиков.

Геймпад — вторая независимая привязка того же действия: запись дополняется `gamepadKeys`, `gamepadDefault`, `gamepadConflict` (например, `keys: "Ctrl+P"`, `gamepadKeys: "View+Y"`). Команды `hotkeys.gamepad.set {id,keys}` и `hotkeys.gamepad.reset {id}` объявляются в `availability` только при реализации адаптером; через клавиатурную команду геймпадная комбинация не назначается.

- Пустая строка в `keys` снимает только эту привязку; сброс тоже касается только выбранного устройства.
- Конфликты одинаковых комбинаций проверяются внутри устройства, в том числе при сбросе.
- Запись комбинаций: модификаторы клавиатуры Ctrl, Alt, Shift; кнопки геймпада View, Menu, A/B/X/Y, LB/RB, LT/RT, L3/R3, ↑/↓/←/→; разделитель `+`.
- Назначения хранит адаптер, они работают в активном окне игры независимо от сайта. Порог срабатывания курков и фронт комбинации определяет адаптер; страница назначения игровых действий не исполняет.

`state.settings: {gamePath,dataPath}` — для страницы настроек; изменение пути — `settings.set {key,value}`, если адаптер это поддерживает. Ничего из этого не выводится на основную панель.

## Закреплённое (UI-18)

`state.pins: [{key, values?}]` — список закреплённого в порядке меню; команда `pins.set {items}` сохраняет его целиком в пользовательских данных. Ключи: `cheat:<id>`, `staging:prepare`, `staging:action`, `snapshots:retake`, `snapshot:<id>`, `look:<id>`; `values` — количество разового действия на момент закрепления (`{count:5}`). Адаптер хранит список как данные пользователя и не проверяет смысл ключей; несуществующие ключи сайт просто не показывает. Без `pins.set` в `availability` сайт хранит список в браузере.

Ответ на `cheat.set` с отказом сайт откатывает к подтверждённому значению из `state`, в том числе на закреплённом контроле.

## Страницы проекта

`config.json → pages: [{id,title,module}]` добавляет страницы, нужные одной игре. `module` — путь к файлу внутри сайта, например `./pages/scenes/index.js`, который экспортирует `mount(section, context)`, как встроенные модули. Ядро сайта при этом не правится. URL страницы — `?page=<id>`.


## Только выбранные модули

Данные и команды дополнительных возможностей находятся в ADAPTER.md соответствующего выбранного модуля. Общий контракт не требует читать их все.

Выбранный UI на старте читает состояние и затем обновляет его. Ползунок применяет значение после короткого объединения частых изменений; обновление состояния не сбрасывает редактируемое поле. Жесты/горячие клавиши обрабатываются в активном игровом окне адаптером; браузерные обработчики не подменяют игровой ввод.

Шаблон — готовая визуальная основа и транспорт, не универсальный инжектор. До выдачи хелпера пользователю отключить деморежим и подтвердить функции реальной игрой.
