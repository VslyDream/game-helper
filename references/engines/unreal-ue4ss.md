# Unreal Engine + UE4SS (Lua)

Опыт **одного проекта** (Toybox: UE 5.8, UE4SS `v3.0.1-1161`, Lua-мод, кооп): частные решения, не стандарт. Пометки [V] — проверено там.

## 1. Распознать

- `<Project>/Binaries/Win64/<Project>-Win64-Shipping.exe`, `<Project>/Content/Paks/*.pak` (+ `.utoc/.ucas` в UE5). Версия движка — свойства exe, строки в нём или лог в `%LOCALAPPDATA%\<Project>\Saved\Logs\` [I].
- Сейвы обычно `%LOCALAPPDATA%\<Project>\Saved\SaveGames\*.sav` [I].
- Античит (EAC/BattlEye) — стоп, как в `unity-detect.md` §8.

## 2. Загрузчик

- UE4SS ставится прокси-DLL рядом с Shipping-exe в `Binaries/Win64`: `dwmapi.dll` + папка `ue4ss/` (`UE4SS.dll`, `UE4SS-settings.ini`, `Mods/`) [V]. Нужна сборка UE4SS, знающая версию движка (для свежих UE — экспериментальные/dev-сборки); номер записать.
- Мод: `ue4ss/Mods/<Имя>/Scripts/main.lua` + строка `<Имя> : 1` в `Mods/mods.txt` [V].
- В `UE4SS-settings.ini` для пользователя выключить консоль и GUI-консоль (`ConsoleEnabled = 0`, `GuiConsoleEnabled = 0`, `GuiConsoleVisible = 0`), горячую перезагрузку — по необходимости [V].
- Для нативной логики и сложных типов есть C++-моды UE4SS; Lua хватило для камеры, читов, повторов [V].

## 3. Поток игры

- Объекты движка трогать только в игровом потоке: `ExecuteInGameThread(fn)` или `LoopInGameThreadAfterFrames(1, fn)` (если есть в сборке) [V].
- `LoopAsync(ms, fn)` — фоновый таймер: чтение файлов/опрос, без обращений к UObject [V].
- Покадровая логика камеры — раз в кадр в игровом потоке, иначе видео дёргается [V].
- Каждый вызов оборачивать `pcall`, ошибку класть в состояние для панели [V].
- `RegisterLoadMapPreHook` — сбросить режимы и кэши при смене карты (фрикамера, полёт, запись) [V].
- Поиск объектов: `FindFirstOf`, `FindAllOf`, `StaticFindObject`; проверять `IsValid()` [V]. Хуки функций: `RegisterHook` / `UnregisterHook`.
- Консольные переменные движка: `KismetSystemLibrary:ExecuteConsoleCommand` (`t.MaxFPS`, `r.VSync`, `r.DOF.*`) — пресеты графики для съёмки; исходные значения запоминать и возвращать [V].

## 4. Сетевые обработчики

Хук на сетевую функцию (RPC) выполняется в чувствительном месте. Чтение массивов структур (`TArray` в аргументах) из Lua-обработчика RPC роняло хост: стек `push_structproperty → TArray`. Решение: в обработчике брать только объект и скалярные id, поиск по массиву — в игровом обновлении; хуки подключать только на время записи [V].

## 5. Связь с панелью

Сделано файлами: `bridge/request.json`, `response.json`, `state.json`, `input.json` в `%LOCALAPPDATA%\<Мод>\`; мод опрашивает раз в ~12 мс, сервис ждёт ответ с тем же `id`; запись атомарная (`.tmp` → rename) на стороне сервиса [V].

Минусы: опрос и задержка, гонки чтения/записи, «принято» раньше «выполнено», мусорные файлы. Для нового проекта предпочтительнее HTTP или TCP на `127.0.0.1` из C++-мода или через сокет-библиотеку Lua — проще отлаживать и есть поток событий [I].

Ввод фрикамеры там шёл из сервиса: низкоуровневые хуки клавиатуры/мыши + Raw Input + XInput, состояние кнопок передавалось в мод; хоткеи — только при фокусе окна игры [V].

## 6. Установщик

- Ищет игру через Steam `libraryfolders.vdf`, иначе спрашивает папку [V].
- Сверяет **SHA-256 exe** с манифестом (`sha256`, `previousBuilds`, совместимые хэши для снимков); не тот билд — отказ без изменений файлов игры [V].
- Перед обновлением копирует прошлую версию мода и загрузчика в `rollback/` + `state.json`; `Rollback.cmd`, `Remove.cmd` [V].
- Встроенный Python (`runtime/`) и `Start.vbs` — пользователю ничего ставить не нужно; сервис без консоли [V].
- Подробности упаковки — модуль «Распространение» (`modules/distribution/SPEC.md`).

## 7. Проверки

Отдельная копия игры, отдельный профиль, `-nosteam` для локальных прогонов; журнал проверок по билдам (`VERIFICATION.md`); пробы-скрипты на каждую гипотезу [V]. Кооп двумя аккаунтами и физический геймпад — в «проверить руками» (DEV-08).
