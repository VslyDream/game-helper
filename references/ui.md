# 2. Интерфейс и игровые читы

Обязательная оболочка. Содержательный список читов пользователь задаёт отдельно для каждой игры.

## Страницы и навигация

- **UI-01.** Главная страница — **«🎮 Читы»**. Если включена фрикамера, её секция расположена первой здесь же. Не требуется отдельная страница для каждой группы читов.
- **UI-02.** Постоянная боковая навигация слева: «Читы», затем подключённые «Сохранения», «Записи и повторы», страницы проекта и последней «⚙ Настройки». Меню закреплено: при прокрутке длинной страницы оно остаётся на месте, а если само не помещается по высоте, прокручивается отдельно. На странице читов под ней показаны вложенные ссылки на категории с эмодзи. Это переход к секции той же страницы.
- **UI-03.** У страниц собственные URL, у категорий — якоря. Используются настоящие ссылки: СКМ и Ctrl+клик открывают новую вкладку, работают закладки, обновление страницы и история браузера.
- **UI-04.** Выключенные модули и пустые категории скрыты целиком, без пустых карточек, неработающих кнопок и призывов их включить. Если камеры нет, страница продолжает называться «Читы».
- **UI-15.** Страница **«⚙ Настройки»** — для редкого: хоткеи хелпера, путь к игре, папка пользовательских данных. Хоткеи можно переназначить нажатием нужной комбинации; хелпер сразу предупреждает о конфликте с другим хоткеем хелпера и с известными клавишами игры, у каждого есть «Сбросить». На основной панели рядом с действием остаётся только короткая метка клавиши.
- **UI-16.** Страницы, нужные одной игре (сцены, армия, карта и т. п.), подключаются через `config.json → pages` без правки ядра сайта, см. [контракт](../contracts/adapter.md). Они ведут себя как встроенные: свой URL, место в меню перед «Настройками».
- **UI-05.** Сверху — короткий статус подключения и запуск/закрытие игры. Сообщение об операции появляется только по необходимости. Не добавлять большой приветственный экран, декоративные метрики и повторяющие заголовок описания.

## Плотность и контролы

- **UI-06.** Компактная сетка с одинаковой логикой отступов. Настройки группируются по смыслу, но большая плашка под один маленький переключатель не нужна. Короткие ползунки располагаются в две–три колонки при достаточной ширине.
- **UI-07.** У каждой функции один основной орган управления: переключатель — для режима, ползунок — для диапазона, числовое поле — для точного количества, список — для вариантов, кнопка — для разового действия.
- **UI-08.** Рядом с ползунком видны значение и единицы. Шкала удобна в рабочем диапазоне; у фокуса логарифмическая. Точное значение можно задать без многократного перетаскивания. Зависимые представления одного параметра не получают два самостоятельных ползунка.
- **UI-09.** Понятная подпись, эмодзи у категории или смыслового блока, короткий хоткей рядом с действием. Эмодзи помогают поиску и не заменяют названия.
- **UI-10.** Частые действия видны сразу. Редкие и дополнительные настройки — в раскрывающемся блоке внутри своей секции. В карточках галереи вторичные действия находятся в «•••».
- **UI-11.** Изменение переключателя/ползунка применяется согласованным способом без лишней кнопки «Применить» для каждого контрола. Для разовых операций с числом отдельная кнопка уместна. Обновление статуса не прерывает редактирование поля.
- **UI-12.** Одно действие не дублируется несколькими равнозначными кнопками. Если инструмент управляется мышью/хоткеем в игре, панель показывает его включение, настройки и статус; отдельные кнопки каждого жеста добавляются только по необходимости.
- **UI-13.** Внешний вид по умолчанию — спокойная тёмная панель с читаемым текстом и одним акцентом, близкая к текущему хелперу. На узком окне сетка перестраивается, значения и кнопки не обрезаются. Компактность не достигается нечитаемым шрифтом.
- **UI-14.** Во время ввода текста на сайте игровые хоткеи и колёсико не выполняют игровые команды. Основные элементы доступны с клавиатуры, имеют подписи и заметный фокус.

## Карточка требования к конкретному читу

Для каждой выбранной пользователем функции фиксируются только необходимые сведения:

| Поле | Что согласовать |
|---|---|
| Название и категория | Где искать функцию |
| Поведение | Что именно меняется в игре и что считается успехом |
| Контрол | Кнопка, переключатель, диапазон, выбор варианта |
| Значение | Начальное значение, единицы, границы и точный ввод при необходимости |
| Ввод в игре | Хоткей/жест, если он нужен; конфликты с игрой и камерой |
| Доступность | Меню/уровень, соло/хост/клиент и другие реальные условия |
| Жизненный цикл | Что происходит при выключении, смене карты и перезапуске |

Наборы вроде «Персонаж», «Мир», «Вид и время» — примеры категорий, а не обязательный список читов. Не добавлять бессмертие, спавн, отключение теней, управление предметами и другие функции без выбора пользователя. Графические пресеты не включать автоматически и не менять ими исходный вид игры при выключенном режиме.

## Приёмка

1. По одной странице читов можно быстро найти каждую выбранную функцию через боковую навигацию; меню не уезжает при прокрутке.
1. Хоткей переназначается на странице настроек, конфликт виден до сохранения, метка на панели обновляется.
2. Страницы открываются СКМ, после обновления сохраняется нужная страница/секция.
3. У контролов нет лишних дублей, пустых плашек и длинных одиночных ползунков на всю страницу.
4. UI показывает реальный результат и остаётся удобным при частом обновлении статуса.
