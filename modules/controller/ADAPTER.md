# Контракт считывания контроллера

Ресурсы UI: `assets/site/modules/controller/`.
Провайдер Python: `assets/runtime/controller_input.py`.
Генератор копирует их только при явном выборе `controller`.

## Подключение к локальному сервису

```python
from controller_input import ControllerService

controller = ControllerService().start()
try:
    snapshot = controller.snapshot()
    # GET /api/controller/state возвращает snapshot как JSON.
finally:
    controller.stop()
```

`start()` запускает отдельный поток. COM и XInput инициализируются на этом же
потоке. `snapshot()` возвращает независимую копию. Настроенный опрос подключённых
устройств — 120 Гц, поиск пустых слотов — раз в секунду; это не гарантированная
реальная частота и не измерение задержки. Python 3.11+ предпочтителен на Windows
из-за высокоточного `time.sleep`; `Event.wait` здесь давал около 64 Гц.

Сгенерированный `serve.py` уже поднимает этот API по `127.0.0.1`, если `controller`
выбран в `config.json`. API игры он не реализует. Для полноценного хелпера
подключить провайдер к настоящему серверу адаптера, сохранив loopback и проверку
Host/Origin. Не запускать второй провайдер только ради каждой вкладки.

## GET /api/controller/state

```json
{
  "source": "windows",
  "status": "ready",
  "error": null,
  "slotErrors": {},
  "library": "xinput1_4.dll",
  "startedAt": 0,
  "updatedAt": 0,
  "ageMs": 0,
  "samples": 0,
  "devices": [],
  "observed": {}
}
```

Это пример формы, не показания подключённого устройства.
`status` — `ready` или `error`. Пустой `devices` при `ready` означает отсутствие
устройства, а не ошибку библиотеки. `slotErrors` содержит реальные ошибки слотов;
отключение (1167) ошибкой не считается. Времена — Unix milliseconds, `ageMs` —
возраст последнего цикла опроса. `samples` — число циклов, не аппаратная частота USB.

Каждое устройство содержит:

- `id: "xinput:0"`, `slot: 0…3`, отображаемое `name`, `mapping: "standard"`,
  `packet` и `sampledAt`.
- `raw: {buttons,lt,rt,lx,ly,rx,ry}`: маска кнопок, байты курков 0…255,
  знаковые оси −32768…32767.
- `buttons`: `a,b,x,y,lb,rb,back,start,ls,rs,up,down,left,right`, значения boolean.
  Курки передаются отдельно; Guide/Home в обычной маске XInput нет.
- `sticks: {left:[x,y],right:[x,y]}`: −1…1, вверх соответствует отрицательному Y.
  `triggers: {lt,rt}`: независимые 0…1, без мёртвой зоны.

`observed` содержит по каждому слоту нажатые кнопки, минимум/максимум осей и курков,
наличие промежуточных значений, одновременного нажатия курков, число подключений,
отключений и отсчётов. Это история текущего процесса, а не сертификат исправности.
Смена устройства в одном слоте не различается; отчёт подписывается пользователем
только после сверки физического устройства.

## Страница

`mount(section, context)` возвращает `{dispose()}`; освобождать при уходе со страницы.
`context.config.apiBase` задаёт корень API, `context.controllerApi` может переопределить
полный URL. UI получает Windows-состояние до 30 раз/с. `mountSettings(parent, context)`
добавляет настройку мёртвой зоны, раскладку камеры при наличии `gamepad` и
свёрнутую диагностику. Возвращает `{dispose()}`. Страница —
`?page=settings#controller-check`; постоянного пункта контроллера в меню нет.

Браузерный источник использует `navigator.getGamepads()` и `requestAnimationFrame`.
Стандартные позиции кнопок применяются только при `mapping === "standard"`.
После активации вкладки может требоваться нажатие кнопки устройства.

При отсутствии ответа/свежих данных 700 мс UI обнуляет значения. Игровой адаптер
сам проверяет свежесть: сеть/страница не являются циклом управления камерой.
Не путать неизменившийся `packet` с потерей связи: неподвижный контроллер
законно возвращает одинаковое состояние при успешных свежих чтениях.

## Проверенные особенности Windows

Структуры имеют размеры 12/16 байт. Перед вызовами провайдер инициализирует COM:
на проверенной системе без этого XInput возвращал `0x800401F0`.
`.js` и `.mjs` сервер явно отдаёт как JavaScript, независимо от ассоциаций реестра.
DLL загружаются через `ctypes.WinDLL`, аппаратный драйвер не устанавливается.

Провайдер только читает. Не применять `XInputEnable(false)` как способ выключения
ввода в чужой игре. Механизм подавления действий персонажа выбирается в игровом
адаптере и проверяется на конкретной игре.
