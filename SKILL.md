# Игровой хелпер

Используй эту папку как переносимый стандарт для нового игрового проекта. Хелпер нужен, чтобы **снимать игру для трейлеров и роликов**: свободная камера, чистый кадр, управление временем, погодой и ИИ, повторяемые дубли. Это задаёт приоритеты исследования и предложений. Список функций задаёт пользователь; наличие модуля в папке не означает, что его нужно реализовать.

Работа идёт этапами; читай документы своего этапа, а не всё сразу: **исследование** (шаги 1, 4) → **предложения** → **сайт и адаптер** (шаги 2–3, 5) → **приёмка** (6).

1. Из сообщения пользователя и `PROJECT.md` определи игру, путь, выбранные модули и конкретные читы. Не добавляй опциональные модули автоматически. Значимые противоречия уточни; остальное решай по контексту.
2. Перед сайтом и адаптером прочитай [запуск](references/core.md), [правила UI](references/ui.md), [компоновку](references/layout.md) и [контракт адаптера](contracts/adapter.md). [Процесс разработки](references/process.md) и [исследование](references/research.md) — с самого начала.
3. Прочитай **только выбранные** требования и соответствующие ресурсы сайта:

| Запрос | ТЗ | Ресурсы |
|---|---|---|
| Фрикамера | `modules/freecam/SPEC.md`, `ADAPTER.md` рядом | `assets/site/modules/freecam/` |
| Геймпад камеры | `modules/freecam/GAMEPAD.md` | Отдельная интеграция ввода игры |
| Считывание / диагностика контроллера | `modules/controller/SPEC.md`, `ADAPTER.md`, `VERIFIED.md` рядом | `assets/site/modules/controller/`, `assets/runtime/controller_input.py` |
| Сохранения | `modules/snapshots/SPEC.md`, `ADAPTER.md` рядом | `assets/site/modules/snapshots/` |
| Повторы камеры или игроков | `modules/replays/SPEC.md`, `ADAPTER.md` рядом | `assets/site/modules/replays/` |
| Распространение / GitHub | `modules/distribution/SPEC.md` | Только выбранные способы доставки |
| Управление из чата (MCP) | `modules/mcp/SPEC.md` | MCP-сервер поверх локального API |
| Справочник предметов / сущностей | `modules/catalog/SPEC.md` | `assets/site/modules/catalog/` |
| Постановка сцены | `modules/staging/SPEC.md` | `assets/site/modules/staging/` |

Повтор камеры требует фрикамеру. Повтор игроков требует [исходного мира](contracts/world-state.md), но не страницу сохранений. Свободный наблюдатель требует фрикамеру. Геймпад и распространение по умолчанию выключены. При несовместимом выборе покажи зависимость, не подключай крупный модуль скрыто.

`controller` — независимое считывание и диагностика, без обязательной фрикамеры.
`gamepad` — управление фрикамерой; прежняя зависимость от `freecam` сохранена.
Не включай `controller` автоматически при выборе камеры: если он нужен, выбери явно.
Для повторного использования ввода начни с проверенного провайдера и его ограничений,
а подавление действий персонажа реализуй и проверь отдельно в адаптере игры.

Для выбранных физических/визуальных читов можно прочитать соответствующий раздел `references/optional-patterns.md`; весь файл не является обязательной базой.

4. Изучи игру по [циклу исследования](references/research.md): `scripts/recon.py` → **один** плейбук движка из [references/engines/](references/engines/README.md) → маршрут в `MODDING_PLAN.md` → матрица `docs/00_capabilities.md`. Шаблоны документов — `templates/docs/`, каркас плагина Unity IL2CPP + BepInEx 6 — `templates/plugin-il2cpp/`, цикл сборки и CLI агента — `templates/tools/`. Ведёшь `MODLOG.md`; одна ошибка трижды — стоп-кран. Известные грабли — [pitfalls.md](references/pitfalls.md), только нужные разделы. После изучения дай короткий список предложений сверх заказанного (DEV-09) и не делай их без выбора пользователя. Не переноси команды, пути, классы и частные исправления предыдущей игры. Не обещай функции только на основании макета.
5. Начни сайт с `assets/site/`; генератор `scripts/create_project.py --help` копирует только выбранные модули и ТЗ. Заполни профиль игры и настоящий адаптер. Деморежим служит проверке интерфейса, не считается подключением к игре.
6. Проверь приёмку выбранных модулей в игре. Отдельно сообщи: что работает, что ограничено и что не проверено. Удалённые модули не оставляют UI, запросов и перехватов ввода. Непроверенное — отдельным списком «проверить руками» (DEV-08).

Сохраняй компактность, боковую навигацию, настоящие ссылки, один регулятор размытия и привычные хоткеи. Не добавляй поясняющие плашки и дубли кнопок. Настройки и включённые режимы между запусками (кроме паузы и заморозки) и отделение пользовательских данных обязательны. Распространение не является обязательной частью разработки и само по себе не разрешает публикацию.

Категории читов вложены сразу под «Читы», а не под остальными страницами.
«Настройки» закреплены отдельно снизу меню. Диагностика контроллера раскрывается
внутри настроек. Для одного действия поддерживай независимые клавиатурную и
геймпадную привязки; ручное назначение обязательно, считывание нажатия — опционально.
«Постановка» — отдельная страница. Частые действия любой страницы пользователь
закрепляет в блоке «📌 Закреплённое» над «Настройками» (UI-18).
