# Шаблоны документов исследования игры

Копируются в `docs/` проекта в начале работы (DEV-01). Новый агент или новый чат начинает с `knowledge-card.md`, затем `MODLOG.md` (последние записи), затем нужные номера.

## Что куда

| Файл | Что пишем | Когда |
|---|---|---|
| `knowledge-card.md` | короткая карточка игры: стек, маршрут, что работает, грабли | обновлять в конце каждого этапа |
| `MODLOG.md` | журнал шагов: что сделал, результат, что дальше | после каждого значимого шага |
| `MODDING_PLAN.md` | цель, стек, маршрут и почему, лаборатория, первый срез, риски | до начала работы; секцию «Стек» заполняет `scripts/recon.py --out` |
| `00_capabilities.md` | матрица возможностей игры для съёмки → основа предложений DEV-09 | после первого прохода по коду |
| `01_overview.md` | игра, режимы, сцены, цикл игрока | |
| `02_engine.md` | стек, загрузчик, версия сборки BE, как отключить мод, логи | после recon и первого запуска загрузчика |
| `03_saves.md` | где сейвы, формат, слоты, бэкап, одноразовый слот | до любых операций со слотами |
| `04_input.md` | система ввода, карты действий, переназначение, геймпад | |
| `05_systems.md` | камера, время, HUD, ИИ, персонаж, спавн — где что в коде | |
| `06_dangerous_keys.md` | опасные клавиши и команды (DEV-03) | до назначения хоткеев мода |
| `07_builds.md` | билды игры: build id, SHA-256, что сломалось (DEV-04) | при каждом обновлении игры |

`STATE.md` и `DECISIONS.md` в корне проекта и `docs/CHECKS.md` — не про игру, а про работу: итог последнего большого хода и что открыто; решения пользователя с датой; полный список «не сделано» и «проверить руками» (DEV-08).
Карточка игры и номерные документы отвечают «как устроена игра», `MODLOG.md` — «что делали по шагам»; одно в другое не переписывать.

Новые темы — следующими номерами (`08_…`, `09_…`), не вставлять между существующими. Номер = порядок чтения. Большие таблицы и выгрузки — в `docs/data/`, в документе ссылка и вывод.

## Пометки (DEV-02)

- **[V]** — проверено в игре (лог, скриншот, состояние через API). Указывать, как проверено, если не очевидно.
- **[I]** — выведено из кода, названий, ассетов. Перед обещанием пользователю проверить.
- **[W]** — из веб-источников / сообщества, на этой игре не проверено. Указать источник и дату.

Без пометки утверждение не пишется. Уточнения через пробел: `[V Demo]`, `[V офлайн]` (проверено без запуска игры, например компиляцией).

## Правила

- Декомпиляция, дампы, interop-сборки и выгрузки ассетов хранятся **вне репозитория/папки проекта** (или в игнорируемой папке), не публикуются и не попадают в дистрибутив. В документах — только имена классов/методов и выводы, без больших кусков кода игры.
- Пути к классам — полностью: `Namespace.Class.Method(args)`; для IL2CPP-полей — имя как в interop.
- Если вывод опирается на конкретный билд — указать build id (см. `07_builds.md`).
- Пишем коротко: таблицы и списки, одно утверждение — одна строка. Рассуждения — в `MODLOG.md`, итог — сюда.
